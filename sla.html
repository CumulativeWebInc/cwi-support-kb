Support tiers — response & resolution targets

Coverage: the machine runs 24/7; owner-only decisions (spending, wallet signing, identity, paid accounts) queue to Black and are never agent-acted.

Escalation path

  1. Triage first: answer from the KB runbooks (index.html RB-01..RB-12) → reproduce → only then escalate.
  2. Content/KB issue → CWI_Guide.
  3. Monitoring/pipeline anomaly → CWI_Watch.
  4. Engineering authority (deploys, gates, CTO calls) → KingCode — deploy gate owner.
  5. Anything naming Black personally, wallets, credentials, spending, paid accounts, or security → Black, same day, his decision — never agent-acted.

Hard lines (never relaxed): no spending; no wallet signing; no credentials handled; nothing under Black's personal name; never promise fixes, dates, or payouts — only state what is verified.

SLA measurement

How is SLA compliance measured?
Per tier: % of issues acknowledged within target, % with substantive response within target, % resolved-or-escalated within target. Target: ≥90% on all three per tier, reviewed weekly. Breaches post to the weekly briefing with the fix attached.
