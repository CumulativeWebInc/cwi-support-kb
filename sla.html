What counts as a "ticket" — and how time is measured

Definitions (v2.0 — charter-aligned)
  • Ticket / issue: any user problem or request reaching CWI_Care/CWI_Guide through the published intake (GitHub issue support template, hp@cumulativeweb.com, or an in-product contact path). Spam and abuse are excluded and labeled as excluded.
  • The clock starts at the received timestamp (stored UTC, displayed US/Eastern). Calendar hours, not business days. v1.2's business-day framing is retired: the charters measure in calendar hours (24h / 72h), so the page does too.
  • Acknowledge: first confirmation a real agent received the issue, with content. An auto-receipt alone does not count.
  • Substantive response: an answer, a verified workaround, or a named next step with an owner.
  • Resolution: verified resolution confirmed with the user — an issue is closed by verified resolution, not by replying. Escalation: handoff with evidence to ENG-REL (bugs), CWI_Affairs (economy disputes), or KingCode (Black's name, wallet, credentials, security).
  • Fair time: time the desk is waiting on required info from the user is logged as "awaiting user" and excluded from the elapsed time. Owner-only topics (spending, wallet signing, identity, paid accounts) queue to Black personally — the queue time is shown, not hidden.
  • Only due tickets count against us. A ticket counts toward a compliance rate only once its target deadline has passed — a ticket answered early is a hit; a ticket whose deadline hasn't arrived is pending, never a miss.
Defined 2026-10-01 · A11 (OPERATION BEST, Wave 2). Validator: tools/sla-validate.js recomputes every flag from timestamps.

The honest-downgrade rule (A11 plan kill rule)
  1. Measured: every ticket is logged in sla-compliance.jsonl with unit, tier, received/acknowledge/response/resolve timestamps, and per-target hit/miss flags recomputed by tools/sla-validate.js (the validator disagrees with the log → the log is rejected).
  2. Published: the rolling 30-day log is public at sla-compliance.html — the full ticket-level table, not a summary number. Never backfilled: no ticket is entered for a day when logging was not live. Measurement began 2026-09-23 (v1.2); zero tickets were ever filed; v2.0 targets took effect 2026-10-01.
  3. Honest downgrade, never silent: 30 days with SLA missed on >20% of tickets → the published target is downgraded to what we actually achieved — the change is dated, announced in the log, and the old target is kept visible as history. A downgrade proposal itself triggers the Care charter review rule. Misses are never deleted and never re-labeled.

Escalation path

  1. Triage first: answer from the KB → reproduce → only then escalate.
  2. Content/KB issue → CWI_Guide.
  3. Monitoring/pipeline anomaly → CWI_Watch.
  4. Engineering authority (deploys, gates, CTO calls) → KingCode — deploy gate owner.
  5. Anything naming Black personally, wallets, credentials, spending, paid accounts, or security → Black, same day, his decision — never agent-acted.

Hard lines (never relaxed): no spending; no wallet signing; no credentials handled; nothing under Black's personal name; never promise fixes, dates, or payouts — only state what is verified.
