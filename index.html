RB-02. What is the memory read/write standing law?
Every task begins with node ~/workspace/cwi-agent-memory/cli/memory.js read agent:X and ends with durable claims written (claim/source/date/confidence). read agent:X returns ONLY the shared pool + agent X's own namespace — claims written to another agent's own namespace are invisible to you. RB-09. Why can't we trust the GitHub Contents API response body?
For 3 blobs in cwi-agent-memory, the Contents API returned wrong bytes (797 vs true 536) while reporting the correct blob sha — consistently, across retries. The git blob endpoint (/git/blobs/{sha}) returned the true bytes. Authority hierarchy: git/blobs > contents/sha > contents/content-field. Always take the sha from the Contents API and fetch the bytes from git/blobs. (The repo was never corrupt — only the read path was.)
